Source of truth: audit-edit-trail.md. Status: ready.

Problem

The audit log does not show who created or changed a party, account or item, or what a settings save changed. A CA cannot answer "who changed this GSTIN, and from what?"

Solution

Every create, edit and status change of these records writes a row. An edit stores each changed field with its old and new value. Audit stays fire-and-forget (owner decision, 2026-10-09).

A1 — Audit page

R1 Details lists each changed field as Label: old → new, in form order, joined by " · ". Empty shows "—"; true/false show Yes/No; lists join with ", ".
R2 New labels: Party created/changed, Account created/changed, Item created/changed, Item status changed, Payment method created, Payment method status changed.
R3 On shows the record's name; search finds it.
R4 Description: "Changes to your books, records and settings, and every permission denial".
R5 Older rows render as today.

F1 — Writing the trail

R6 party, account, item and paymentMethod create write { name } after commit.
R7 party, account, item and settings update write { name, changes }; changes holds only differing fields as [old, new].
R8 A save with no change writes no row.
R8a item and paymentMethod setActive follow account.setActive: { name, active } on every success; account adds name.
R9 A refused write writes no success row.
R10 Money as formatDecimal under keys without "Paise"; references as names; never ids, normalizedName or updatedAt.
R11 Fire-and-forget: a failed audit write never fails or slows the edit.

Out of scope

  • Audit writes inside transactions.
  • Editing posted documents in place; Amend stays.
  • Per-row audit for imported records; draft edits.
  • Renaming Amend to Edit.

Deferred

  • Retention and backups: already an Operations go-live gate.
  • CA review of the MCA wording before any compliance claim.

Open questions

None.

Contracts

  • auditChanges(before, after) in packages/db/src/audit.ts returns Record<string, [AuditValue, AuditValue]> | undefined. AuditValue is exported from packages/db/src/schema/audit.ts.
  • Updates read the old row in their transaction under the same edit-token predicate; a missing row is the existing stale refusal.
  • setActive takes the name from its update's returning.
  • item.update records income account names read in the same transaction.
  • describeMeta renders meta.changes; labels add PAN, PIN and HSN/SAC.
  • No schema change. docs/architecture.md lists the new events.

Test seams

  • tests/integration/account.test.ts: a rename writes changes: { name } only.
  • Same file: a stale update writes no row.
  • Audit page checked in the running app.
